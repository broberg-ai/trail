# F191.5 — Free-run upmetrics telemetry

Parent: [F191](./F191-local-ingest-station.md).

## Why
Christian's requirement: local ingest must STILL report to upmetrics even though the compute is $0. The cost panel should show local ingest VOLUME (free runs) next to paid cloud ingest — otherwise self-implemented-customer ingest is invisible.

## Scope
The compile runs in a cc session (no ai-sdk in the loop), so the report is stamped **server-side** when the engine receives the local-ingest trail MCP write. Detect attribution via the F95 `mcp:claude-code` connector. Emit a free agent_run to upmetrics: `{ agentName:'trail', capability:'ingest', provider:'anthropic', transport:'subprocess', costUsd:0, subprocess:true, labels:{tenantId,kbId}, purpose:'local-ingest' }`. Reuse the existing upmetricsSink/connector machinery; the key never leaves the engine.

## Open
Token counts: the cc session may not expose its own usage to itself — record run-count + $0 with tokens null/estimated if unavailable (the value here is volume + free/metered split, not exact tokens).

## Verify
Run a real local-ingest compile; confirm a free run appears in `/api/cost/summary?tag.tenantId=<t>` with cost 0 + incremented `metered.free_run_count`, NOT a paid run.

## Dependencies
F191.2 (compiles happen), F95 connectors, upmetricsSink (lib/ai.ts), the cost API (F014/F190.5).
