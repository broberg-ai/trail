# F201.14 — Live ordbog-correction + dictionary-mining from ambient sources

> Status: planned (2026-07-03) · Parent: F201 (Trail Ambient Capture) · Area: ambient-capture app + engine + shared dictionary
> Depends on: F201.13 (ambient sources — the raw material to mine), F201.6.7 (Apple streaming STT)
> Related: @broberg/speech-dictionary (fleet component, components-owned, not yet on npm); cardmem F044.1 (dictionary edit-API)

## Motivation

Apple's STT mishears dev/domain terms — "WhisperKit" → "vise på kit", product
and person names, jargon. Two problems, one dictionary solves both:

1. **The transcript should show what the user REALLY said, live.** Christian
   (2026-07-03): a known `wrong → right` correction does not ALTER the words, it
   **RESTORES** them — Apple merely misheard. So applying the ordbog to the
   transcript yields the faithful original. The correction must run **live**, on
   each streaming partial, so the HUD self-corrects as he speaks.
2. **The dictionary must grow from real usage.** New mishearings that aren't in
   the ordbog yet can only be found by looking at real captured speech. The
   F201.13 ambient-speech sources are exactly that corpus — mine them for
   candidate new `wrong → right` pairs and surface them for approval.

## Design

### The dictionary data

`corrections{ wrong: right }` + `terms[]` (canonical names). Source of truth is
the fleet component **@broberg/speech-dictionary** (components-owned). It is not
on npm yet, so **interim**: derive the map from the seed `ordbog.txt` (~70 pairs,
format `forkert -> korrekt (forklaring)`, at
`/Users/cb/Apps/cbroberg/openai-whisper-docker/ordbog.txt`) and bundle it. Swap to
the npm package (`data/corrections.json` + `data/terms.json`) when it ships — no
call-site change if we keep an `applyCorrections(text)` / `terms()` seam.

### Two layers of accuracy

- **Pre-STT biasing (best-effort):** Apple's `SFSpeechAudioBufferRecognitionRequest`
  accepts `contextualStrings` — feed `terms[]` (canonical dev/product/person
  names) so the recogniser is biased toward them before it even mishears. This is
  the Apple equivalent of WhisperKit's `initialPrompt`.
- **Post-STT correction (deterministic):** apply `corrections{wrong:right}` to
  every streaming partial — word-boundary, case-preserving, no LLM → instant.
  This catches what biasing didn't.

### Where correction applies (Christian's decision)

- **HUD (live):** each partial is corrected before display → the user sees true
  words appear as spoken.
- **ambient-speech source (F201.13):** `content` = the corrected transcript (true
  words). Apple's raw pre-correction output is kept in `metadata.rawTranscript`.
- **Mining is NOT lost:** applying KNOWN corrections doesn't hide UNKNOWN ones — a
  not-yet-in-ordbog mishearing has no correction, so it survives verbatim in the
  content and in `rawTranscript`, ready to mine.

### Dictionary-mining

A periodic pass (engine job or admin action) scans ambient-speech sources'
`rawTranscript` for tokens that look like garbled dev/domain terms not yet in the
ordbog, and surfaces candidate `wrong → right` pairs for Christian to approve.
Approved pairs are written to the dictionary via the components edit-API
(`POST discovery.broberg.ai/api/speech-dictionary/edit`, `x-speech-dict-key`,
diff shape `{addCorrections,...}` — cardmem F044.1). Low-tech v1: a report of the
most frequent unknown tokens; smarter mining (LLM-assisted candidate extraction,
EU tier) later.

## Scope

**In:**
- An `applyCorrections(text)` + `terms()` seam in the app (Swift) and engine (TS),
  fed from the bundled ordbog interim data (npm swap later).
- Live post-STT correction on each HUD partial; `contextualStrings` biasing on the
  recognition request.
- Corrected transcript → source content; raw → `metadata.rawTranscript` (F201.13).
- A dictionary-mining pass over ambient-speech sources producing a candidate-word
  report; approval writes back via the edit-API.

**Non-goals (explicit):**
- Building @broberg/speech-dictionary itself — components owns it (reuse-first);
  we consume it and file gaps.
- The dictionary EDIT UI — cardmem owns it (F044.1); we consume the edit-API.
- OCR/image correction — speech only (OCR mishears differently; separate later).
- Auto-approving mined words into the ordbog — always Christian-approved.

## Dependencies

- F201.13 ambient sources (the raw corpus + `metadata.rawTranscript`).
- Apple STT `contextualStrings` (F201.6.7).
- @broberg/speech-dictionary (interim: bundled ordbog.txt) + components edit-API.

## Rollout

1. Interim dictionary data bundled; `applyCorrections` seam in app + engine, unit-
   tested against known pairs ("vise på kit" → "WhisperKit").
2. Live HUD correction + `contextualStrings` biasing; corrected → source content,
   raw → metadata.
3. Mining report over ambient-speech sources; wire approval → edit-API.
4. Swap bundled data → @broberg/speech-dictionary npm when it lands.
