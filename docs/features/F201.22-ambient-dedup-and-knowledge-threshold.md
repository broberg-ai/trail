# F201.22 — one glance at a window became twelve Neurons

**Card:** trail-F201.22 · **Parent:** F201 (Ambient Capture) · 3 SP · critical

> Owner, minutes after F201.21 restored the write path: *"det vælter ind"*.
> It did. That is the problem, not the success.

## Measured, on the real data

```
48 candidates auto-APPROVED today   →   19 genuinely distinct topics

12×  "Sundhedsprojekt og FDAA-noter"
 8×  "FDAA-projekt og supportopgaver"
 6×  "Status og opgaver i FD Sundhed-projektet"
```

And this is what passed as **knowledge**:

> "Jeg har 6 noter relateret til FDAA-projektet"
> "Jeg arbejder på projektet fd-sundhed (**muligvis** relateret til sundhedsdata)"

The first restates a sidebar in Notes. The second is the model *guessing* — and
the hedge is sitting in the text that got stored as a fact. Each time the owner
looked at that window, the distiller manufactured another "fact" from the same
label.

## Why this is worse than clutter

Ambient candidates **auto-approve with no human gate** — deliberately, that is
F201.12. So these go straight into the knowledge base he searches and chats over.

Twelve near-identical Neurons about one window degrade retrieval precisely where
he has been working hardest. The single real finding of the day — *"Rettelser og
fund i FD Sundhed"*, carrying an actual validation bug — now sits in the same
result set as eleven restatements of a note count.

**The pipeline is not broken; the filter is.** 0 pending, 483 auto-rejected, 191
approved: the noise gate catches obvious chrome and misses chrome that has been
fluently rewritten. A distilled sentence reads like knowledge whether or not it
contains any — which is this repo's recurring shape once more, now in the output
of an LLM rather than a return value.

## Scope boundary — the owner's condition

> *"husk det er et Trail Ambient filter og ikke noget der ændrer Trail generisk
> er vi enige?"*

Agreed, and it is why both filters land where they do:

| Filter | Home | Why it cannot leak |
|---|---|---|
| Dedup | `packages/ambient-gate` (the relay) | the package is consumed by nothing else |
| Knowledge threshold | `apps/server/src/services/ambient-distill.ts` | already guarded by `isAmbientCandidate` → `connector === AMBIENT_CONNECTOR` |

No change to `packages/core/src/queue`, to the admission policy, or to the shared
compile path. AC6 asserts a **non-ambient** candidate with the same hedge words
and a duplicate twin is judged exactly as before — the condition is measured, not
promised.

## Design

### Dedup runs in the relay, BEFORE the post

Not after. Twelve posts that are later rejected still cost twelve LLM distill
calls and twelve rows; the cheap fix is not making them. The relay already folds
events into session windows, so it is the only place that sees the stream.

A window whose summary is near-identical to one posted inside a rolling recent
set is dropped. Near-identical, not byte-identical: the summaries differ by a
timestamp range while describing the same thing.

### The knowledge threshold runs on the DISTILLED output

Two rules, both derived from what actually got through today:

1. **A hedge is not knowledge.** `muligvis` / `måske` / `sandsynligvis` /
   `ser ud til` means the model inferred from a label rather than read a fact.
   An inference stored as fact is worse than no Neuron.
2. **A restatement is not knowledge.** Distilled content that adds nothing
   beyond the window title and app name is the label wearing a sentence.

### The negative controls carry the weight

Rejecting more is trivial; rejecting more *without* losing the one useful capture
is the actual requirement. So the suite asserts, on the real stored strings:

- the hedged sentence is rejected,
- the note-count sentence is rejected,
- **and "Rettelser og fund i FD Sundhed" still passes.**

If the last goes red, the filter is too tight and the card is not done.

## Cleanup of what already landed

Owner-ordered. Today's duplicates are **rejected with a reason, never deleted** —
one kept per cluster — and only where `connector=trail-ambient-capture` and the
candidate was created today. Verified by reading the counts back from the API,
including that nothing outside that connector moved.

## Non-goals

- Not raising or lowering the ambient auto-approval threshold (F201.8's job).
- Not touching the deny-list or capture itself.
- Not deleting anything. A rejected candidate keeps its record; a deleted one
  removes the evidence that the filter was ever needed.
