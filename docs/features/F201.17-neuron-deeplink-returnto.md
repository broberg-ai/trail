# F201.17 — Ambient search-result click → land on the exact Neuron after login

## Motivation

Clicking a search result in the Ambient app HUD is supposed to open **that
specific Neuron in the right KB** in the Trail admin. The app ALREADY builds the
correct deep-link — `TrailClient.neuronURL(slug:)` returns
`https://app.trailmem.com/kb/<kbId>/neurons/<slug>`, and the admin has the
matching route (`/kb/:kbId/neurons/:slug` → WikiReaderPanel, accepts UUID or
slug).

**The bug is the login gate, not the URL.** When you are logged out, the
deep-link is lost during sign-in:

- `apps/admin-server/src/index.ts` SPA-fallback (`app.get('*')`, ~line 388):
  a request with no `trail-session` cookie → `c.redirect('/login')` — the
  requested path `/kb/<kb>/neurons/<slug>` is **dropped**.
- After login (Google callback → `/wikis`, or magic-link verify → SPA), you
  land on a generic page, never the Neuron you clicked.

## Approach — provider-agnostic returnTo via a gate cookie + SPA consume

Rather than thread `returnTo` through every provider (Google on the engine,
magic-link + GitHub on admin-server — 3 different callbacks), capture it ONCE at
the gate and consume it ONCE where all providers converge: **the SPA booting
authenticated.**

1. **Gate sets the cookie.** In admin-server's SPA-fallback, before
   `redirect('/login')`, set a short-lived readable cookie
   `trail-return-to = <validated path>` (SameSite=Lax, ~30 min, not httpOnly so
   the SPA can read it). Same capture added to the SPA's own
   session-expired bounce (`apps/admin/src/app.tsx` fetchAuthMe `.catch`).
2. **SPA consumes it.** On `fetchAuthMe()` SUCCESS (`app.tsx`), read
   `trail-return-to`; if it passes `safeReturnPath` and isn't the current path,
   clear the cookie and `location.replace(path)`. All providers end by booting
   the SPA authed, so this one consume point covers Google/GitHub/magic-link.
3. **One shared validator.** `safeReturnPath(raw): string | null` in
   `@trail/shared` (single source, imported by both admin-server + SPA):
   accept only same-origin absolute paths (`/…`), reject `//host`, `http(s)://`,
   `/login`, `/api…`. Prevents open-redirect.

## Scope

**In:** the gate cookie (admin-server), the SPA set+consume (admin/app.tsx),
`safeReturnPath` in @trail/shared + unit test. **Out:** any change to the
Ambient Swift app (its deep-link is already correct); reworking the two-layer
auth; GitHub/magic-link provider internals (the consume point is provider-
agnostic so they need no per-provider change).

## Files

- `packages/shared/src/safe-return-path.ts` (+ export) — validator.
- `packages/shared/src/safe-return-path.test.ts` — accept/reject unit test.
- `apps/admin-server/src/index.ts` — set `trail-return-to` at the `/login` gate.
- `apps/admin/src/app.tsx` — set on session-expiry bounce; consume on auth success.

## Verification

- Unit test (CI-gateable): `safeReturnPath` accepts `/kb/abc/neurons/split-brain`,
  rejects `//evil.com`, `https://evil.com`, `/login`, `/api/x`, ``, non-strings.
- Runtime: logged-out open of a Neuron deep-link → login → lands on the Neuron
  (verify via Lens against the admin, or a manual pass). Logged-in open → lands
  directly (no regression).

## Harness note

Login is load-bearing. The validator carries the RED unit test (open-redirect
reject cases); the change is additive (a lost path today simply becomes a
preserved path) and never weakens the existing session/CSRF checks.
