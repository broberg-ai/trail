# F201.13 — Ambient raw material as first-class Trail **Sources**

> Status: planned (2026-07-03) · Parent: F201 (Trail Ambient Capture) · Area: server/ingest + ambient-capture app + admin
> Depends on: F201.6 (capture + STT), F201.11 (ambient distill), F201.12 (ambient mode)
> Follow-up: F201.14 (live ordbog-correction + dictionary-mining from ambient sources)

## Motivation

Ambient capture produces **raw material** — dictated speech, screen OCR, screen
images. Until now that raw stream had nowhere durable to live: the capture went
`candidate → distill → Neuron`, and distill **rewrote** it into a bullet summary,
so the user's actual words were lost the moment they were spoken ("men ikke det
jeg sagde", Christian 2026-07-03). A failed POST, a distill rewrite, or a crash
lost the raw entirely.

Christian's requirements for a fix:
1. **Never lose the raw** — an interim catch of everything said/captured, kept
   verbatim, independent of the lossy distill pipeline.
2. **Central in the cloud** — survives device loss, queryable across
   devices/sessions, re-processable.
3. **Capture ALL raw ambient material** — speech + OCR + images.
4. **Usable** — to look back / audit, to debug, as training data, and to **mine
   for new words that belong in the speech dictionary** (ordbog).
5. **Do NOT pollute the curated knowledge layer** — the raw is not a Neuron.

**The insight (Christian): "Det ER JO en Source."** The raw ambient material is
exactly what Trail already models as a **Source** — the input material that
compiles into curated wiki Neurons. We reuse Trail's existing Source model
instead of building a bespoke support DB. Every requirement above is satisfied by
Trail's existing source→compile→Neuron machinery:

| Requirement | Satisfied by |
|---|---|
| Never lose raw | Sources are stored verbatim + permanent (that's what a source IS) |
| Central cloud | Sources live in the KB's cloud DB (per-tenant), already central |
| All raw types | Three new source `fileType`s: `ambient-speech`, `ambient-ocr`, `ambient-image` |
| Look back / debug / training / mining | Open the source, read the raw; export; mine the raw text for ordbog gaps |
| Raw ≠ Neuron | Source (`kind='source'`) is a distinct layer from Neuron (`kind='wiki'`) |
| Provenance | `document_references` already links a Neuron claim → its source |

## Design

### Zero-migration data model

`documents.kind` is already an enum `['source','wiki','work']`; `documents.file_type`
is **open text**. So ambient raw = a `kind='source'` document with a new
`fileType`:

- **Ambient Speech** — `kind='source'`, `fileType='ambient-speech'`. Content =
  the dictation transcript with the **ordbog corrections applied** (F201.14) —
  i.e. the user's TRUE words. Christian's point (2026-07-03): a known
  wrong→right correction (e.g. "vise på kit" → "WhisperKit") does not ALTER what
  was said, it RESTORES it — Apple merely misheard. So the corrected text IS the
  faithful original. Apple's raw pre-correction output is kept alongside (in
  `metadata.rawTranscript`) for debug / training / measuring STT error-rate. New
  (not-yet-in-ordbog) mishearings survive uncorrected in the content and remain
  mineable — applying KNOWN corrections doesn't hide UNKNOWN ones.
- **Ambient OCR** — `kind='source'`, `fileType='ambient-ocr'`. Content = the raw
  per-window OCR dump (what F201.11 distill currently eats).
- **Ambient Images** — `kind='source'`, `fileType='ambient-image'`. The captured
  frame; described via the existing F191.7 local-vision flow, description stored
  as the source body.

No schema migration for the core. (An optional index on `(kb, file_type)` can
come later if the Sources filter needs it.)

### Pipeline change: candidate-first → source-first

Today: `ambient app → POST /queue/candidates → distill → Neuron` (raw discarded).

New: `ambient app → create SOURCE (raw, persistent) → compile (distill) → Neuron`,
with the source kept and the Neuron linked back to it.

- The **ambient-capture app** creates a **source** (not a candidate) carrying the
  raw material + `metadata.connector='trail-ambient-capture'`, `metadata.source`
  ∈ `audio|ocr|image`. The raw is stored on the source verbatim.
- The **compile step** = the existing F201.11 ambient distill, now run as the
  source's compile: it emits the curated wiki Neuron(s) and records a
  `document_references` row (`sourceDocumentId` = the ambient source,
  `wikiDocumentId` = the Neuron) so provenance is explicit.
- Distill that returns `noise` → the source is still persisted (raw is never
  lost), but no Neuron is emitted (matches F201.12 ambient-mode noise handling).
- Auto-approval (F201.8/.12) still governs whether the emitted Neuron lands
  approved — unchanged.

### Admin surface (reuse the Sources UI)

The ambient sources appear in the existing **Sources** list, filterable by the
three `fileType`s. This is the "se tilbage / debug / training / mining" surface —
no new interface, just new source types flowing into the one that exists. Each
source shows its raw body and links to the Neuron(s) it compiled into (and vice
versa via `document_references`).

## Scope

**In:**
- New source `fileType`s `ambient-speech` / `ambient-ocr` / `ambient-image`
  recognised across ingest + the Sources filter.
- A source-create ingest path the ambient app calls (raw → `kind='source'` doc).
- Compile wiring: ambient distill runs as the source's compile; emits Neuron +
  `document_references` provenance; raw source persists regardless of verdict.
- Ambient-capture app switched from `POST /queue/candidates` to source-create.
- Admin Sources list recognises + labels the three ambient types.

**Non-goals (explicit):**
- Live ordbog-correction + dictionary-mining → **F201.14** (separate, depends on
  these raw sources existing).
- Re-distilling historical Neurons that were created candidate-first before this
  lands (one-off backfill considered separately; the 119 existing ambient-test
  Neurons stay as-is).
- Changing the on-device capture/STT itself (F201.6) or the auto-approval policy
  (F201.8/.12).
- Cross-device raw sync UI beyond "it's central, open it in admin".

## Architecture sketch

```
ambient-capture (mac)
  dictate / OCR / frame  ──► raw material
        │  (local interim catch: DictationJournal, F201.6.8 — already shipped)
        ▼
  POST create-source  ──►  documents row  kind='source'
                            fileType ∈ ambient-speech|ambient-ocr|ambient-image
                            content = ordbog-corrected (true words, F201.14)
                            metadata.rawTranscript = Apple's raw output (debug/train)
        │
        ▼  compile (F201.11 ambient distill, EU/Mistral, redacted on-device first)
  wiki Neuron (kind='wiki')  ── document_references ──►  ambient source
        │
        ▼  F201.8/.12 auto-approval policy (unchanged)
  approved Neuron  (curated knowledge)      raw source stays, forever, browsable
```

## Dependencies

- F201.6 capture + STT (produces the raw); F201.6.8 local interim catch (shipped).
- F201.11 ambient distill (becomes the source compile step).
- F201.12 ambient mode (noise handling / auto-approve on the ambient KB).
- Provenance: existing `document_references` table.

## Rollout

1. Add the three `fileType`s + a source-create ingest path (ship-dark behind the
   existing ambient env flags).
2. Wire compile + `document_references`; keep the old candidate path working
   until the source path is proven (no naked cutover — harness contract).
3. Switch the ambient-capture app to source-create; verify raw source persists +
   Neuron links back, end-to-end, with a scripted probe (verify-before-claim).
4. Surface the three types in the admin Sources filter.
5. Only then retire the candidate-first ambient path.

## Open questions

- Source-create endpoint: reuse the uploads/ingest route with a text body, or a
  dedicated `POST /api/v1/knowledge-bases/:kb/ambient-source`? (Leaning
  dedicated — the ambient app's shape is text+metadata, not a file upload.)
- One source per dictation vs. rolling/session-grouped sources for OCR frames
  (speech = one per dictation is obvious; OCR frames may want grouping).
