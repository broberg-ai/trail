# F191.2 — `/local-ingest` cc skill + buddy-instantiated pickup

Parent: [F191](./F191-local-ingest-station.md).

## Pickup — buddy instantiates the work (the remediation-job pattern)

Christian's refinement: deliver ingest jobs **exactly the way upmetrics creates remediation jobs for cc sessions** — via buddy. The Station (or a server hook) uses buddy to instantiate an ingest job in a cc session (the same channel that delivered remediation task #441 to this very session today; `mcp__buddy__launch_agent` can even spin one up). **buddy = delivery; the skill = execution.** This is a proven, decoupled mechanism — "any cc session" can receive + run it. (A pure manual `/local-ingest` drain of the pending queue still works as the fallback when a session is already open.)

## The skill — the $0 in-session compile driver

`.claude/skills/local-ingest.md`. When invoked (by a buddy-dispatched job or manually) in an interactive session:
1. Resolve the active tenant/KB.
2. Query awaiting-local-compile sources (F191.1 `?awaitingLocalCompile=true`) via trail MCP / REST.
3. For each: fetch the extracted content + the Trail compile prompt, compile IN-SESSION (claude itself = $0 Max-plan), `write` the Neuron(s) into the cloud KB via trail MCP, clear the flag → source moves to Success.
4. The engine's free-run telemetry (F191.5) fires on the write.

Mirrors the existing `/reingest` compile-only semantics; the compute is the human's session instead of cloud OpenRouter. Reuses the compile prompt from `apps/server/src/services/ingest.ts` (fetched, not duplicated).

**Honours the F191 invariant:** the skill compiles via the session's own MCP work — never `claude -p`, never an API key.

## Dependencies
F191.1 (awaiting-local-compile state + query, shipped); trail MCP write; buddy (delivery); the compile prompt template.
