# F196.6 — trail-widget cannot be built, and prod has been serving a May image since

**Status:** backlog · **Parent:** [F196](F196-deploy-self-report-upmetrics.md) · **Found:** 2026-08-29, while shipping F196.5

## What was measured

`pnpm ship:widget` fails at the build step:

```
src/trail-chat.ts(88,10):  error TS2339: Property 'dispatchEvent' does not exist on type 'TrailChat'.
src/trail-chat.ts(139,12): error TS2339: Property 'dispatchEvent' does not exist on type 'TrailChat'.
src/trail-chat.ts(151,12): error TS2339: Property 'dispatchEvent' does not exist on type 'TrailChat'.
src/trail-chat.ts(166,24): error TS2339: Property 'shadowRoot' does not exist on type 'TrailChat'.
 ELIFECYCLE  Command failed with exit code 2.
```

Four errors, all the same shape: a custom element that does not appear to extend
`HTMLElement` as far as the compiler is concerned, so the DOM members it uses are
unknown. `flyctl` is never reached, so nothing deploys.

**The consequence had been live for months without anyone noticing.** Read off
the running machine, not the repo:

```
image                    trail-widget:deployment-01KRHYM9ZCKXC5JZB5DV520110   (May)
/docker-entrypoint.d/    10-listen-on-ipv6…  15-local-resolvers…
                         20-envsubst…        30-tune-worker-processes…
                         ← no 99-report-deploy.sh
```

So `widget.trailmem.com` answers 200 from an image that predates the deploy
self-report entirely. That is why it alone still says `no_release` while the
engine, admin and docs all report `87212b3`: there is nothing in that container
to report with. `git log -- apps/widget/` shows its last three touches are all
fleet-wide changes (F196, F196.5, a test commit) — nobody has shipped it since
the build broke.

## The second finding, and it is mine

I ran `pnpm ship:widget 2>&1 | tail -5` and read `exited with code 0`. **The 0
came from `tail`, not from the ship.** The build had failed four lines earlier.
I was one step from reporting the widget as deployed.

Same family as everything else this week — a success-shaped signal that reports
something other than what was asked. Here the instrument was my own command
pipeline: a pipe discards the exit status of every stage but the last, and
`ELIFECYCLE ... exit code 2` scrolled past inside a green-looking result.

Worth carrying beyond this card: **when a command's exit code is the thing you
are about to report, do not pipe it.** Capture it (`set -o pipefail`, or check
`${PIPESTATUS[0]}`), or read it explicitly.

## Scope

**In:** the four TS errors, fixed at the type level; a shipped widget; its
release-register row.

**Out:** any behaviour change to the widget itself. This card makes it
buildable and shippable, nothing more — if the chat element needs work, that is
its own card measured on its own terms.

## Note

Do not "fix" this with `any`, `@ts-ignore` or a looser tsconfig. Four errors
that all say the same thing point at one missing declaration, not four
problems — silencing them would ship a widget whose element contract is a
fiction, and the next person to touch it would inherit both the bug and the
lie.
