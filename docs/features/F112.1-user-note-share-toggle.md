# F112.1 — Per-Neuron opt-in share for "Din tanke"

> Lille checkbox under each user-note der lader curator opt-in til at dele *denne specifikke* note med chat og eksterne integrationer. Default OFF (samme privacy-stance som F112), men curator kan flippe pr. Neuron når de vil have deres egen vinkel med i konteksten. Tier: alle. Effort: Tiny — ½-1 time. Status: Planned.

## Problem

F112 shippede user-note med en hård "deles aldrig"-regel i hint-teksten. Det gav privacy-garantien tid til at lande, men Christian flagged 2026-05-05: "egne tanker kan jo i princippet være med uden at der sker noget — det er meta-data". For curator der har lagt 5 minutter ind i en velformuleret refleksion er det frustrerende at vide den kun lever i deres eget reader-view.

Sat anderledes: F112's privacy var et default, ikke et axiom. En per-Neuron opt-in respekterer både dem der vil have noten privat (default) og dem der bevidst vil have egne ord med i chat/integrations-svar.

## Solution

Tilføj `user_note_share` boolean kolonne på documents (default 0). En lille checkbox under hver "Din tanke"-textarea: "Anvend også i chat og eksterne integrationer". Når checked = note inkluderes i `chat.ts retrieveContext` og `retrieve.ts` payload som adskilt sektion mærket som curator's egen formulering.

Hint-teksten skiftes fra "deles aldrig" til "deles kun hvis du tikker boksen" så curator forstår begge sider af switchen.

## Non-goals

- **Global setting** — pr-Neuron giver curator finest control. Global "share all my notes" er for grovkornet og risikabelt.
- **Granular share-targets** ("share med chat men ikke med eksterne") — to switches er for meget weight på én lille widget. Hvis det viser sig at være need senere, kan vi splitte.
- **History af share-toggle ændringer** — én boolean uden audit-log. Hvis curator unsharer en note efter den allerede er blevet brugt i et chat-svar, kan vi ikke "tage det tilbage" — chat-historikken viser stadig svaret. Det accepterer vi.

## Technical Design

### Schema migration 0034

```sql
ALTER TABLE documents ADD COLUMN user_note_share integer NOT NULL DEFAULT 0;
```

`integer` boolean (SQLite-konvention), default `0` så alle eksisterende noter (alle private fra F112) forbliver private.

### Endpoint udvidelse

`PUT /api/v1/documents/:docId/user-note` body får ny optional field:

```typescript
{
  userNote: string,
  share?: boolean,  // optional; falsy = private (default)
}
```

Hvis `share` ikke er sat på request, beholder kolonnen sin nuværende værdi (idempotent på flag-changes).

`GET /content` returnerer både `userNote` + `userNoteShare` så reader kan checke checkboxen korrekt på mount.

### Chat-input integration

I `retrieveContext` (chat.ts), når en chunk's parent document har `user_note_share=1` AND non-null `user_note`, tilføj noten som adskilt sektion i context-blokken:

```
### chunk [Header]
<chunk content>

### Curator's reflection (their own words)
<user note>
```

LLM får dermed eksplicit signal om hvad der er den oprindelige Neuron vs. curator's egen formulering — det er pædagogisk vigtigt så modellen ikke bløder grænserne ud.

### Retrieve (F160) integration

`retrieve.ts` payload får ny `userNote: string | null` field pr. chunk. NULL hvis: ingen note ELLER `share=0`. Eksterne consumers (Sanne's site-LLM-orchestrator) kan vælge at vise noten som "Sannes egen vinkel" eller bare bruge den som ekstra signal til deres LLM.

### UI

Under textarea, lille checkbox-row:

```tsx
<label class="flex items-center gap-2 mt-2 text-[11px] text-[color:var(--color-fg-muted)] cursor-pointer">
  <input
    type="checkbox"
    checked={share}
    onChange={(e) => setShare(e.target.checked)}
    class="accent-[color:var(--color-accent)]"
  />
  <span>{t('wikiReader.userNote.shareLabel')}</span>
</label>
```

Save flytter både text + share-flag i samme PUT.

### i18n updates

- Hint-tekst skiftes fra "Den deles aldrig med chat eller eksterne integrationer." til "Default privat — tikker du boksen nedenfor deles den med chat og eksterne integrationer som 'din egen formulering'."
- Ny string `shareLabel`: "Anvend også i chat og eksterne integrationer"
- Ny string `shareHint`: "LLM ser det som adskilt sektion mærket som din egen formulering, ikke som Neuron-indhold"

## Rollout

Single-phase deploy. Migration additive (default 0 = matches F112 behavior), så eksisterende noter forbliver private uden ændring.

## Success Criteria

1. Migration 0034 lander og kolonne har default 0 på alle eksisterende rows.
2. PUT med `share: true` flipper kolonnen; PUT uden `share`-felt lader den stå.
3. GET /content returnerer både userNote + userNoteShare.
4. Chat retrieveContext inkluderer user_note som "Curator's reflection" når share=1, ellers ikke.
5. F160 retrieve returnerer userNote field pr. chunk når share=1, ellers null.
6. Checkbox UI persisterer korrekt mellem reloads.
7. Default-toggle adfærd (når curator ikke explicit klikker) holder note privat.

## Effort estimate

**Tiny** — ½-1 time.
