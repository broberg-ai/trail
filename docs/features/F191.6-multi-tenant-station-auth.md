# F191.6 — Multi-tenant Station auth (one key, all my tenants)

**Parent:** [F191 — Local Ingest Station](F191-local-ingest-station.md)
**Status:** building
**Owner:** trail cc session

## Motivation

The Ingest Station (F191.3) auto-logs-in on localhost with a personal
`trail_` key from `.env.local-ingest` (F191 CLI + auto-login). That key is
**bound to ONE tenant** (`control_api_keys.tenant_id`, F188) — currently
`broberg-ai`. But Christian's primary need is to land source material into
**Sanne Andersen's** trail too, and he wants to do it **without physically
logging in** — just keep the auto-login and "give me more privileges."

So: the auto-login key must span **every tenant Christian is a member of**,
and the Station must let him pick which one he's dropping into.

## Prod reality (verified 2026-06-04 against trail-admin `/data/control.db`)

This is far simpler than F188's "Phase 2+ cross-tenant" sketch assumed:

- **One org**: `org-sanne-andersen` (slug is historical; it IS the org).
- **Two tenants, both in that org, both on the same engine** (trail-engine-001 /
  `engine-001.trailmem.com`): `broberg-ai` ("Broberg.ai") + `sanne-andersen`
  ("Sanne Andersen").
- `cb@webhouse.dk` (`u-cb-webhouse`) is **`owner` on BOTH** via
  `control_memberships`.
- Each tenant has its own per-tenant engine bearer in `tenant_engines.bearer`
  (the multi-tenant engine's key-index maps bearer→tenant DB).

So no new orgs, no new memberships, no engine routing changes are needed —
only a key that resolves to a chosen membership tenant per request.

## Scope

**In:**
1. **`scope='all'` personal key.** Reuse the existing `control_api_keys.scope`
   text column (no migration). `scope='all'` = "spans the owning user's
   memberships"; `scope='full'` (current) = single-tenant, unchanged.
2. **Per-request tenant selection** via an `X-Trail-Tenant: <slug>` header.
   `proxy.ts::resolveApiKey` for a `scope='all'` key verifies the slug is one
   the key's user has a `control_memberships` row for, then routes to that
   tenant's engine + bearer. No header → falls back to the key's home
   `tenant_id` (so the key still works unscoped).
3. **`GET /api/control/my-tenants`** (key-authed, admin-local, NOT proxied) —
   returns the tenants the key's user is a member of `[{slug,name,role}]`. A
   non-`all` key only sees its home tenant (no enumeration leak). Populates the
   Station's tenant picker.
4. **Station tenant picker** — a custom popover (mirrors `KbPicker`; NO native
   `<select>`) in the header. Selecting a tenant persists it (localStorage),
   sends `X-Trail-Tenant` on every call (REST + SSE + upload + wiki-write +
   recompile), and reloads the KB list for that tenant.
5. **Logo + real identity** in the header — the Trail concentric-circle mark
   (admin `favicon.svg`) + lowercase mono `trail` wordmark + `ingest` subtitle,
   rendered with the Station's own tokens. Plus a tab favicon.
6. **Mint `cb@webhouse.dk` a `scope='all'` key**, write it into
   `.env.local-ingest`, revoke the old single-tenant key.

**Non-goals:**
- RBAC enforcement on roles (owner/admin/member) — every membership is
  accessible; role is display-only here (F187 territory).
- Cross-**org** keys — there is only one org; not needed.
- Engine routing changes — both tenants are on one engine; the per-tenant
  bearer already scopes the engine DB.
- Cookie/magic-link session in the Station — explicitly rejected (Christian
  does not want a physical login).

## Architecture

```
Station (localhost, auto-login trail_…all key)
  │  GET /api/control/my-tenants           → admin-local (key-auth) → [broberg-ai, sanne-andersen]
  │  every /api/v1/* call + X-Trail-Tenant: sanne-andersen
  ▼
admin proxy resolveApiKey(scope=all)
  │  header slug ∈ user memberships?  → tenant + tenant_engines.bearer
  ▼
trail-engine-001  (bearer → key-index → that tenant's trail.db)
```

Security: a `scope='all'` key can only reach a tenant the **owning user** has a
`control_memberships` row for — the header is a *selector*, not a grant. An
unknown/forged slug → 401 (membership check fails). Legacy `scope='full'` keys
are untouched and ignore the header.

## Verification

- Prod round-trip: with the `scope='all'` key, `GET /knowledge-bases` +
  `X-Trail-Tenant: broberg-ai` returns broberg-ai KBs; same call with
  `sanne-andersen` returns Sanne's KBs; a bogus slug → 401.
- `/api/control/my-tenants` returns both tenants for cb's key.
- Negative: a `scope='full'` key + `X-Trail-Tenant: <other>` still resolves
  ONLY its home tenant (header ignored).
- Browser note: tenant-picker click flow is typecheck-verified + wired to the
  prod-verified endpoints; explicit browser-click only if Chrome DevTools MCP
  is wired.

## Rollout

1. Ship admin-server (`pnpm ship:admin`) — adds resolveApiKey scope-handling +
   `/my-tenants`. Additive, no migration.
2. Mint cb's `scope='all'` key, update `.env.local-ingest`, revoke old key.
3. Station picks up the picker + logo on next `trail ingest` (Vite rebuild).
