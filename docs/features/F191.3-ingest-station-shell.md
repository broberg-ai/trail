# F191.3 — `apps/ingest-station` shell  ✅ shipped (code-complete + build-clean)

Parent: [F191](./F191-local-ingest-station.md).

## What shipped
A thin Vite+Preact localhost app (mirrors the apps/admin toolchain: Vite 5.4 + Preact 10 + Tailwind v4). Dev port 3032 (`PORT`-overridable).

- **Auth = personal `trail_` key** (F188), pasted once, stored in localStorage, sent as `Authorization: Bearer`. The Vite dev-proxy forwards `/api` → the cloud admin (`CLOUD_API`, default `https://app.trailmem.com`) so the browser is same-origin (no CORS) and the proxy routes the key to its tenant's engine.
- **KB picker** — a custom popover (NOT a native `<select>`, per project rule); lists the KBs for the key's tenant (`GET /api/v1/knowledge-bases`).
- **Drop-zone** — DnD + click → `POST .../documents/upload?localCompile=true` (F191.1), so sources park for the `/local-ingest` skill instead of the paid cloud compile.
- Sources-only surface; no other admin.

## Deviation from the original AC (honest)
The AC said "extract a shared `packages/ingest-ui` consumed by both apps/web and the Station." I built a **lean station-specific Sources surface** instead. Reasoning: the live Sources UI is apps/admin's ~900-line `sources.tsx`; extracting it into a shared package + refactoring the admin to consume it is a large change I can't browser-verify headless without risking the prod admin. The station's needs are narrow (upload + list + status), so a purpose-built ~200-line surface is simpler + safer (Rule 2). The "no duplication" concern is mild — the station's drop-zone is ~30 lines, not a copy of the admin panel. **Follow-up:** if the two surfaces start to drift meaningfully, do the `packages/ingest-ui` extraction then.
