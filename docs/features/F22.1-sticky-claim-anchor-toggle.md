# F22.1 — Sticky claim-anchor toggle in wiki-reader header

> Per-context shortcut to flip claim-anchor visibility while reading a Neuron, without leaving the reader to go to Settings → Visning. Same global preference (showClaimAnchors signal, persisted in localStorage), just a second entry-point. Tier: alle. Effort: Tiny — ½ time. Status: **Dropped 2026-05-03** (built then reverted same day — see "Outcome" at bottom).

## Outcome (2026-05-03)

Built and shipped at 16:00. Christian asked 16:30: "Hvad er pointen ved at brugere kan se de claim tags?" and the answer was honest: for end-users, none. Claim-anchors are an internal cross-reference primitive consumed by lint detectors, F78 trust-tiers, and cross-Neuron citations like `[[other-neuron#claim-xxx]]`. The audiences that benefit:

- Lint + system: read DOM `id=` attributes, no UI needed
- Sanne (end-user reading her own Neurons): zero benefit
- Power-user wanting to copy a claim-id: right-click → Inspect already works
- ADR/citation author: rare enough that the dedicated curator-panel coming with F78 is the right home

Per-context toggle solved a problem nobody actually had. Reverted at 16:35. Settings → Visning toggle stays for the rare power-user who wants markers globally visible (same use-cases above, just less aggressive UI weight). Plan-doc kept for institutional memory of "we tried it, here's why we stopped."

## Problem

F22 ships claim-anchor visibility as a global preference toggled from `/settings` → Visning. That works as the canonical home for the setting, but it forces a context-switch when the curator notices a claim-id they want to copy or deep-link to: navigate away from the Neuron → toggle → navigate back. Cognitive cost > the value of the canonical home.

Christian flagged this 2026-05-03 directly after F22 shipped: "Måske en bruger indstilling til Globalt om man vil se claims" — he wanted both the global home AND a quick-flip in flow.

## Solution

Add a small icon-button to the wiki-reader header next to the existing "Edit" button. Click → flips the same `showClaimAnchors` signal that `/settings` flips. The CSS-toggle (`.claims-hidden .claim-anchor { display: none }`) reacts instantly because the signal drives the wrapper-class on the article body.

Visual: the same `#` glyph the inline anchors use, with `aria-pressed` reflecting state. Tooltip changes between "Vis claim-anchors" and "Skjul claim-anchors" depending on current state. No badge, no count, no second UI surface — minimal weight.

## Non-goals

- **Per-Neuron pinning.** Toggle is global; flipping it on Neuron A also affects Neuron B. Per-Neuron state is overkill for an internal cross-reference primitive.
- **Per-section visibility.** "Show claim-anchors only on headings" is fancy filtering we don't need; either you want them or you don't.
- **Click-to-copy claim-id.** The inline `<a class="claim-anchor" href="#claim-xxx">` already deep-links via URL fragment; copy comes from the address bar.
- **Visual indicator on the toggle for "off and there are claims to see"**. Considered and rejected — that's a permanent yellow nudge for a setting most users will leave off intentionally.

## Technical Design

### State

Reuses the existing `apps/admin/src/lib/claim-anchors-pref.ts` module. No new state.

```ts
import { showClaimAnchors, setShowClaimAnchors } from '../lib/claim-anchors-pref';
```

To make the toggle reactive (Preact's `useSignals` so the button re-renders when the signal flips from another tab/panel), the wiki-reader imports `useSignals` from `@preact/signals` and calls it once at the top of the component.

### Render

In the existing `<header>` block of `wiki-reader.tsx`, between the "← Neurons" back-link and the "Edit" button:

```tsx
<button
  type="button"
  onClick={() => setShowClaimAnchors(!showClaimAnchors.value)}
  aria-pressed={showClaimAnchors.value}
  title={t(showClaimAnchors.value
    ? 'wikiReader.claimAnchors.hide'
    : 'wikiReader.claimAnchors.show')}
  class={
    'px-2 py-1 rounded-md border text-sm font-mono transition ' +
    (showClaimAnchors.value
      ? 'border-[color:var(--color-accent)]/40 bg-[color:var(--color-accent)]/10 text-[color:var(--color-accent)]'
      : 'border-[color:var(--color-border)] text-[color:var(--color-fg-subtle)] hover:text-[color:var(--color-fg)]')
  }
>
  #
</button>
```

The article-body's `class={...claims-hidden}` derivation already references `showClaimAnchors.value`, so the toggle propagates without extra wiring.

### i18n

```json
{
  "wikiReader.claimAnchors.show": "Vis claim-anchors",
  "wikiReader.claimAnchors.hide": "Skjul claim-anchors"
}
```

## Rollout

Single deploy via `pnpm ship:admin`. No server changes, no DB migration.

## Success Criteria

1. Toggle appears in wiki-reader header.
2. Click flips `.claim-anchor` visibility instantly across all currently-open wiki-reader instances + the article body.
3. `/settings` toggle and header toggle stay in sync (same signal).
4. Refresh preserves state (localStorage round-trip works).
5. `aria-pressed` reflects state for screen-readers.

**Tiny** — ½ time.
