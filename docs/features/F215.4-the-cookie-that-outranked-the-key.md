# F215.4 — A browser cookie silently outranked the API key

**Status:** in progress · **Parent:** [F215](F215-web-clipper-tenant-picker.md) · **Reported by:** the owner, in the product, 2026-08-28

## What he saw

> "Uanset hvilken Tenant jeg vælger så defaulter den til Sanne Andersen trail"

The tenant picker shipped, appeared, and listed all three customers correctly.
Choosing a different one changed nothing: the Trail list stayed Sanne's, every
time.

## The measurement

Three facts, taken from production, that only one explanation fits:

1. **The engine is correct.** Called directly with each tenant's own engine
   bearer, from inside the admin machine:

   ```
   sanne-andersen   200   1 KB: Sanne Andersen
   broberg-ai       200  10 KB: CB-M1 | Buddy Research | … | Zoneterapi (demo)
   fd-aalborg       200   1 KB: Admin Chat
   ```

2. **The built extension is correct.** The installed `0.2.0` bundle contains the
   header code, minified but intact:
   `function ze(e,t){const n={Authorization:...};return t&&(n["X-Trail-Tenant"]=t),n}`

3. **His new key had `last_used_at: null`.** Minted 14:38:55, scope `all`, home
   tenant `t-sanne-andersen` — and never used. The proxy stamps `last_used_at`
   on every key-resolved request. So the Trail list he was looking at **was not
   fetched with his key at all.**

Fact 3 is the one that settles it, and it was sitting in the same query as the
scope I went there to check.

## Root cause

`apps/admin-server/src/proxy.ts`:

```ts
const route = (await resolveSession(c)) ?? (await resolveApiKey(c));
```

The session cookie is tried FIRST. Christian is signed in to `app.trailmem.com`
in the same Chrome, and a Chrome extension holding `host_permissions` for that
origin sends its cookies. So every Clipper call arrived with both credentials,
and the cookie won.

`resolveSession` picks its tenant from the **`trail-active-tenant` cookie** and
never looks at `X-Trail-Tenant` — correctly, for the Admin SPA, which is the
caller it was written for. The result is that the Clipper's picker set a header
nobody on the winning path reads.

Why `/api/v1/me/tenants` looked healthy while the KB call did not: that route is
mounted BEFORE the proxy and reads the bearer first, so the picker was populated
from the key while the list underneath it came from the cookie. **One surface,
two different identities** — the day's recurring shape, and the reason the
picker could look like it worked.

## Why this is worse than a picker that does nothing

The Clipper's tenant picker is a promise about **where a clipped page is
stored**. It named Broberg.ai and would have written into Sanne Andersen. It has
not yet, because the KB id is cleared on every switch and the ids of one tenant
do not exist in another — so the clip would have failed rather than landed in
the wrong customer. That is luck holding the line, not design.

The same hole applies to the Ingest Station whenever it is opened in a
signed-in browser.

## Fix

**Server — the real fix.** An explicitly presented `trail_` bearer wins over an
ambient cookie. Presenting a key is an instruction to act AS that key.

```ts
const presentsKey = /^bearer\s+trail_/i.test(c.req.header('authorization') ?? '');
const route = presentsKey ? await resolveApiKey(c) : await resolveSession(c);
```

And a presented key that fails to resolve is a **401**, never a fallback to the
cookie. Falling back is what let a dead key look alive: the first `web-clipper`
key was revoked at 14:38 and the popup went on listing Trails regardless.

**Client — defence in depth.** The Clipper sends `credentials: 'omit'` on every
call. It acts as its key; it has no business carrying the user's browser
session. This alone would have prevented the bug, and it is the layer that keeps
preventing it for any future endpoint that resolves credentials in the wrong
order.

## Non-goals

- Changing how the Admin SPA resolves its tenant (the `trail-active-tenant`
  cookie stays exactly as it is).
- Teaching `resolveSession` to read `X-Trail-Tenant`. A browser session's active
  tenant is UI state; making a header override it would give any page on the
  origin a way to steer the session's tenant.

## Rollout

One commit across `apps/admin-server` + `apps/web-clipper`. The server fix is
what unblocks him; the extension rebuild ships with the next Store version.
Requires a `trail-admin` deploy — the owner's call, not taken here.
