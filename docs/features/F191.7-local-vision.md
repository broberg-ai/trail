# F191.7 — Local vision (defer image description to the $0 cc session)

**Parent:** [F191 — Local Ingest Station](F191-local-ingest-station.md)

See the full plan-doc in the repo. Summary: F191 made COMPILE $0 but image VISION still ran on paid cloud Haiku during extraction — both for standalone image sources (inline describeImageAsSource) and for images embedded in PDF/DOCX/PPTX (the vision-rerun job, which fires regardless of awaitingLocalCompile). F191.7 defers both to the multimodal cc session.

## In scope
1. Gate cloud vision on awaitingLocalCompile (uploads.ts): standalone image → deferred $0 placeholder describeImageAsSource; embedded → skip the vision-rerun job submission.
2. REST endpoints: GET /documents/:docId/raw (source bytes), GET /documents/:docId/images?pending=1 (null-description embedded images), POST /documents/:docId/images/:filename/local-vision (write desc, vision_model='claude-code', cost 0). Standalone desc via existing PUT /documents/:docId/content.
3. /local-ingest skill image step: image source → /raw → Read → describe → PUT /content; any source → drain pending embedded images via Read + local-vision; then compile. All $0 (cc turn-reasoning, never claude -p / API key).

## Non-goals
Per-image free-run telemetry; changing the cloud path; feeding embedded descriptions into compile; auto-flag parity.

## Verify
Standalone image $0 parked; PDF embedded → no vision-rerun job, rows NULL; list+write round-trip; negative: non-localCompile still paid. Rollout: pnpm ship (additive, no migration) + skill update + real drop test.
