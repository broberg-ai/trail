# F215.3 — Two endpoints answer "which tenants may I select?", and they already disagree

**Status:** in progress · **Parent:** [F215](F215-web-clipper-tenant-picker.md) · **Owner:** cc

## Motivation

Building F215.1 yesterday I wrote `GET /api/v1/me/tenants` for the Web Clipper's
tenant picker. `GET /api/control/my-tenants` (F191.6) already existed and answers
the same question for the Ingest Station. I did not notice until after it shipped.

That is not a tidiness complaint. **Measured today, the two already disagree in
four ways** — and one of the disagreements is a wrong value on a screen:

| | `/api/control/my-tenants` (F191.6) | `/api/v1/me/tenants` (F215.1) |
|---|---|---|
| auth | bearer only | bearer **+ session cookie** |
| shape | `{scope, tenants:[{slug,name,role}]}` | `{tenants:[{slug,name,home}]}` |
| order | whatever the JOIN returns | home first, then alphabetical |
| narrow key | home tenant, **`role` hardcoded `'member'`** | home tenant, no role |

The last row is the live defect. `apps/admin-server/src/keys.ts` returns a
**constant** for a single-tenant key:

```ts
tenants: home ? [{ slug: home.slug, name: home.name, role: 'member' }] : [],
```

and `apps/ingest-station/src/app.tsx:366` renders `{t.role}` next to the tenant
name. So the Station prints `member` beside a tenant the caller may own. The
value is not a reading of anything — it is a literal that happens to be printed
where a reading belongs. It cannot be wrong in a way anyone would notice, which
is exactly why it survived.

This is the day's recurring shape one more time: **one signal, two facts.** Two
endpoints, both returning 200 with a plausible tenant list, and no way to tell
from either response that they would not agree with each other.

## Scope

**In:**

- `selectableTenants()` in `apps/admin-server/src/me-tenants.ts` becomes the
  single place the membership question is answered. It gains `role`, read from
  the `control_memberships` row.
- `/api/control/my-tenants` keeps its URL and its exact response shape, but
  projects from that function instead of running its own JOIN.
- `/api/v1/me/tenants` unchanged on the wire.
- One verify script that asserts the two answers against **each other**, not
  each against a hand-written expectation.

**Out (explicit non-goals):**

- **Deleting `/api/control/my-tenants`.** It is deployed and the Ingest Station
  is a separately-built app; removing the URL before a Station release points at
  the new one is a naked cutover (harness rule 3). Replace, prove, *then* remove
  — and the removal is a later card, not this one.
- Changing the Station's UI, or what it shows for `role`.
- Touching the proxy's own tenant resolution (`resolveApiKey` / `selectTenant`).
  Those enforce access; this card only reports it.

## Architecture

One query, two projections at the edge:

```
control_memberships ⨝ control_tenants
            │
   selectableTenants(userId, homeTenantId, spansAll)
     → [{ slug, name, role, home }]      ← one ordering, one dedup, one truth
            ├── /api/v1/me/tenants   → {tenants:[{slug,name,home}]}     (Clipper, SPA)
            └── /api/control/my-tenants → {scope, tenants:[{slug,name,role}]}  (Station)
```

The shapes stay different on purpose — two shipped clients parse them — but they
can no longer disagree about *which tenants*, because there is only one place
that decides.

`role` for a narrow key: read the caller's membership row for the home tenant.
If there is none (a legacy key whose membership was removed), keep returning the
home tenant with `'member'`, exactly as before. Narrowing that to "return
nothing" would lock a working Station out of a tenant on a code cleanup, and
access is not this endpoint's decision to make anyway.

## Acceptance criteria

See the card. The load-bearing one is the mutation: breaking the shared function
must turn **both** endpoints red. If only one goes red, they are still two
implementations and this card did nothing.

## Rollout

One commit, `apps/admin-server` only. No migration, no client change, no deploy
dependency — the Station and the Clipper both keep parsing what they parse today.

## Follow-up (not this card)

When the Ingest Station next ships, point it at `/api/v1/me/tenants` and retire
`/api/control/my-tenants`.
