# F201.6 — Audio-tap + mic + on-device STT (WhisperKit, VAD)

**Parent:** F201 Trail Ambient Capture (fase F4)
**Status:** in progress
**Depends on:** F201.4 (gate), F201.11 (distill), F201.5 (ScreenCaptureKit TCC already granted), WhisperKit (SPM)

## Motivation

Spoken work — meetings, calls, thinking out loud — is ambient's **highest-value
source**: it's where decisions and knowledge actually happen, and where you're
least likely to take notes. Screen OCR (F201.5) catches what's on screen; audio
catches what's *said*.

Christian's framing (2026-07-02): *"hvad med et video møde jeg kan lave med mig
selv på 2 maskiner?"* — that is both the flagship use-case (capture a meeting →
distilled decisions/notes, zero manual note-taking) and the perfect **test
harness**: join a call from machine A + machine B, both running ambient, and you
have a real two-way conversation to transcribe + distill without a second person.

## Goal

Capture two-way audio on-device, transcribe it privately, and feed the
**transcript** (never the audio) through the existing gate → distill → candidate
pipeline:

- **mic** (AVAudioEngine input) = the local speaker (cb);
- **system audio** (ScreenCaptureKit SCStream audio) = the other side of a call —
  reuses the Screen Recording TCC grant F201.5 already holds;
- **VAD** (voice-activity detection) segments continuous audio into speech spans;
- **WhisperKit** (CoreML Whisper, on-device, da+en, $0) transcribes each span;
- the transcript rides the same path as `FocusEvent.screenText` → F201.4 gate →
  F201.11 distill → candidate. In Ambient-tilstand (F201.12) a spoken decision
  auto-approves into a Neuron; chatter distills to noise and auto-rejects.

**Egress guarantee is structural, same as screen frames:** raw audio is captured,
VAD'd, transcribed and discarded entirely on-device. Only the resulting text
crosses the network. The capture buffer has no code path to the relay.

## Non-goals

- **Speaker diarization** (who-said-what) — a strong follow-up for meeting
  transcripts, but not this story. Note it for F201.6.later.
- **Real-time streaming transcription UI** — batch per-segment is enough for
  knowledge capture; we're not building live captions.
- **Cloud STT fallback** — on-device only. $0 + privacy is the whole point; a
  meeting must never leave the machine as audio.
- **Video/camera frame capture** ("billede/video") — separate story.

## Architecture

- **`Sources/VAD.swift`** — pure energy/RMS voice-activity detector over 16 kHz
  mono PCM frames: `threshold`, `minSpeechMs`, `hangoverMs`. Emits `[Segment]`
  (start/end sample). No I/O → **headlessly unit-testable** on synthetic PCM.
- **`Sources/AudioWatcher.swift`** (actor) — owns the live capture: AVAudioEngine
  mic tap + (F201.6.3) SCStream system-audio tap, downsampled to 16 kHz mono,
  fed frame-by-frame to `VAD`. On segment-complete → WhisperKit transcribe →
  append an `AudioEvent { transcript, startTs, endTs, source }` to the local
  audio log (mirrors `EventLog`/`FocusEvent`). Deny-list honoured — no capture
  while a deny-listed app (password manager, banking) is frontmost.
- **WhisperKit** — SPM dependency (`argmaxinc/WhisperKit`). Model
  (`openai_whisper-base`) loaded from Application Support; **ship-dark**: absent
  model + no network → audio capture stays disabled, no crash, a status line
  says why.
- **TCC** — mic usage string (Guideline 5.1.1(ii)-safe: "Trail bruger mikrofonen
  til at transskribere dine møder på enheden, så beslutninger bliver til noter
  du kan søge i — lyden forlader aldrig din Mac."). Screen Recording already
  granted (F201.5) covers the system-audio tap.
- **Menubar** — an audio status line + a dedicated audio mute/pause (independent
  of the screen/focus pause).

## Capture control & background-noise (Christian, 2026-07-02)

The naive "capture the mic → transcribe everything" is wrong: a TV playing news
or Wimbledon in the background is *coherent* speech, so the distill could mistake
it for knowledge and mint a Neuron out of a tennis commentary. Christian's
decision resolves this with a control model, not a post-hoc filter:

- **Speaker enrollment (the primary filter).** Enrol Christian's voice once; then
  only mic segments matching his voiceprint are transcribed. A news anchor / TV
  voice doesn't match → dropped, even when the TV runs *during* a meeting. The
  call's far side arrives via the **system-audio** tap (F201.6.3), which the TV
  is not part of, so it's preserved. This makes background room-noise a non-issue
  by construction.
- **⌃⌥T "capture now" (deliberate solo capture).** A global hotkey that starts
  audio sampling on the spot — *without* being in a meeting — for when Christian
  has a thought he wants captured. Push-to-capture; he chooses the moment.
- **Audio mute in app settings (the global off).** A dedicated audio on/off in the
  menubar app, independent of the screen/focus pause — the manual escape hatch.
- Meetings may additionally auto-arm capture (a comms app active), but enrollment
  is what makes always-considering-audio safe; the hotkey covers the solo case.

## Phasing (sub-stories)

- **F201.6.1 — VAD core + mic-capture scaffold.** `VAD.swift` (pure) +
  `AudioWatcher` mic capture via AVAudioEngine → segments written as WAV.
  Self-test `--audiotest <wav>` runs the VAD over a file and prints detected
  segments — **headlessly provable**. Live mic mode needs Christian to speak
  once (the one physical step).
- **F201.6.2 — WhisperKit STT.** Add the dependency; transcribe a segment WAV →
  text (da+en). Proof: transcribe a bundled known clip, assert expected words.
- **F201.6.3 — System-audio tap + merge.** SCStream audio (the call's far side)
  merged with mic; the two-machine meeting scenario end-to-end.
- **F201.6.4 — Wire to knowledge.** Transcript → gate → distill → candidate;
  chunked distill for long meeting transcripts (reuse F142).
- **F201.6.5 — ⌃⌥T "capture now" hotkey + audio mute toggle.** Global hotkey
  (reuse `HotKey.swift`) that arms/disarms a solo capture; a dedicated audio
  on/off in the menubar app, independent of the screen/focus pause.
- **F201.6.6 — Speaker enrollment + voice filter.** One-time voice enrolment;
  per-segment speaker verification so only Christian's voice is transcribed
  (SFSpeakerRecognition / on-device speaker-embedding). The robust
  background-noise filter (TV/Wimbledon), including during a meeting.

## Acceptance criteria (F201.6.1, this slice)

1. `VAD` over a synthetic PCM buffer (silence → 1 kHz tone → silence) returns
   exactly one speech segment whose bounds match the tone span within a frame's
   tolerance; a pure-silence buffer returns zero segments.
2. `AudioWatcher` builds and, given a WAV file via `--audiotest <path>`, prints
   the VAD segments (count + start/end seconds) and exits 0 — proving the
   file→PCM→VAD path headlessly.
3. Deny-list guard: `AudioWatcher.capture` is a no-op (no segment, no WAV) when a
   deny-listed app is frontmost, mirroring `ScreenWatcher`.
4. Ship-dark: with no mic TCC grant, the app starts, logs an
   `audio_watcher_untrusted` line, and continues capturing focus/screen — no
   crash, no half-wired audio.

## Verification strategy

- **VAD** — deterministic: synthesise silence/tone/silence PCM in the test, assert
  segment boundaries. Runs in the `scripts/test.sh` harness gate.
- **STT (F201.6.2)** — transcribe a bundled WAV with known content, assert the
  transcript contains the expected words.
- **Live capture** — `--audiotest` live mode Christian runs (speak ~5 s); the one
  physical step CC can't self-drive (mic TCC + real sound).
- **End-to-end (F201.6.4)** — on the 2-machine meeting, a spoken decision appears
  as a distilled Neuron in ambient-test.

## Rollout

Ship-dark by construction: audio capture stays off until the mic TCC grant AND
the WhisperKit model are both present. Deny-list honoured. Zero behaviour change
to the existing focus (F201.3) / screen (F201.5) capture — audio is an additive
watcher.
