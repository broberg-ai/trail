# F215.5 — A masked token with no prefix makes every diagnosis a guess

**Status:** backlog · **Parent:** [F215](F215-web-clipper-tenant-picker.md) · **Raised:** 2026-08-28, from the cost of F215.4

## Motivation

While diagnosing [F215.4](F215.4-the-cookie-that-outranked-the-key.md) the owner
and I spent two full rounds unable to answer one question: **which key is the
Clipper actually using?**

The token field renders dots. Nothing else in the extension names the key. The
only way anyone established the answer was for me to read Chrome's LevelDB files
off his laptop:

```
~/Library/Application Support/Google/Chrome/Default/Local Extension Settings/hapdki…
→ trail_95d866ec…
```

That prefix matched no key in the control plane — which was the whole answer, and
it took a filesystem archaeology detour to get. Meanwhile he re-minted keys and
re-saved them to the vault more than once, because there was no way to tell a
good paste from a bad one.

**A masked secret with no visible prefix is not more secure — it is only less
diagnosable.** The first 12 characters of a `trail_` key are stored in the
database's own `prefix` column precisely so a key can be identified without being
revealed. The Admin SPA already shows it. The Clipper does not.

The 401 message has the same hole. "app.trailmem.com refused the API token (401)"
is true and useless: it does not say WHICH token was refused, so it cannot
distinguish "you pasted an old key", "your key was revoked" and "the server is
broken" — three problems with three different fixes, and we hit two of them in
one afternoon.

## Scope

**In:**

- Under the masked token field: the saved key's first 12 chars + `…`, read back
  from `chrome.storage` (not from the input's local state), or a plain "ingen
  nøgle gemt".
- The 401 banner names the refused prefix.

**Out (explicit non-goals):**

- A reveal / eye toggle that shows the whole key. The prefix answers the question
  the eye button was wanted for, without putting a live credential on screen in a
  window the owner routinely screenshots and pastes into chat. If a full reveal is
  ever wanted it is its own card, with its own argument.
- Any change to how the token is stored.

## Why read-back, not local state

The prefix must come from a fresh `chrome.storage.local.get`, because the failure
it exists to catch is exactly "what I typed is not what got saved". Rendering the
prefix of the input's own value would show the right answer while the wrong one
sat in storage — the same class of lie as a form that says "Saved" without
asking the database. See the fleet rule on read-back in `CLAUDE.md`.

## Rollout

`apps/web-clipper` only. Ships with the next Store version; no server change.
