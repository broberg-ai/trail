# F201.15 — Prompt Mode: dictate straight into a focused cc-session

> Status: planned (2026-07-03) · Parent: F201 (Trail Ambient Capture) · Area: ambient-capture app
> Depends on: F201.6.7 (Apple STT), F201.14 (ordbog-correction), buddy dictate relay (live), FocusWatcher
> Proven live 2026-07-03: a dictate POST to buddycloud dictate landed verbatim as a user turn in the running `trail` cc-session — both from this session and from Christian's own curl.

## Motivation

The Ambient App serves **two purposes**; today only the first exists:

1. **Generic Ambient Extraction → Trail** (mode 1, existing) — capture speech /
   OCR / images, distill, land as curated Trail knowledge (sources → Neurons,
   F201.13).
2. **Prompt Mode** (mode 2, this feature) — turn the app into a **voice input
   device for cc-sessions**. Christian looks at a session (e.g. the iTerm tab
   titled "TRAIL" = this session), dictates a prompt, and the **ordbog-corrected**
   text is relayed **directly into that session's context** as a user turn. He
   speaks instead of typing.

Same capture engine (Apple STT + ordbog-correction), two destinations: Trail
knowledge vs. a live agent prompt. The relay is already proven live — this
feature is the app-side wiring: a mode toggle + resolving which session the
focused tab points at.

## Design

### Mode toggle

A persisted toggle in the HUD/menubar: **Extraction ↔ Prompt**. In Extraction the
finished dictation → Trail (F201.13). In Prompt the finished dictation → dictate
relay to the focused session. The HUD clearly shows the active mode.

### Focus → session resolution — the target auto-switches at runtime (the new bit)

`FocusWatcher` already tracks the frontmost app + focused window/tab title. In
Prompt Mode the target session **follows focus in real time** — as Christian
switches apps/tabs the receiver **auto-updates continuously**, it is NOT resolved
once at dictation start (Christian 2026-07-03: "du skal så bare runtime
automatisk udskifte modtageren efter hvad du tracker af app/tab").

- Front app is a terminal (iTerm) and the focused tab title names a session —
  "TRAIL" → `trail` (lowercased, de-decorated) — that becomes the live target.
- **A persistent, live-updating `Target: <session>` label in the HUD footer**
  shows the current receiver AT ALL TIMES (Christian: "en dynamisk opdateret
  label i bunden af HUD der hele tiden viser Target ... til debug"). It is BOTH:
  - the **safety indicator** — mis-targeting sends your prompt to the wrong agent
    (idea 019f2560; the cctalk mis-delivery is why the target must always be
    visible), and
  - the **debug read-out** for the focus→session resolver.
  It shows `Target: — (ingen session)` when focus isn't on a resolvable session,
  so a mis-send is visibly impossible. (The footer currently shows "Ambient
  Test"; in Prompt Mode it carries this live Target label instead.)
- A **manual override picker** (from buddy `list_sessions`) pins/corrects the
  target when the title mapping is ambiguous or Christian wants to lock it (a
  pinned target stops auto-following until unpinned).

### Dictation → correct → relay

1. Apple streaming STT (F201.6.7) → live text.
2. Ordbog-correction (F201.14) applied → true words.
3. On stop → `POST https://buddycloud.cc/api/seti/v1/dictate`
   `{ session: <resolved>, text: <corrected>, origin: "trail-ambient" }`.
   200 `{ok,session,edge}` → landed. Errors: 401 (token), 404
   (session_not_found → prompt to re-pick target), 502 (edge_not_connected), 400
   (text > 10k).

### Token storage

The dictate token must live in the **app's Keychain** (or app config), NOT the
repo `.env` — the shipped Mac app cannot read the repo working tree at runtime.
(The repo `.env` `TRAIL_AMBIENT_SETI_TOKEN` was only staging for the curl demo.)

## Scope

**In:**
- Persisted mode toggle (Extraction ↔ Prompt) + HUD mode indicator.
- Runtime-auto-switching focus→session resolver (terminal tab title → session
  name, following focus live) + **persistent live `Target: <session>` label in
  the HUD footer** (safety + debug) + pinnable manual override picker (buddy
  `list_sessions`).
- Prompt Mode dictation → ordbog-correct → buddycloud dictate relay, with error
  handling (esp. 404 → re-pick target).
- Dictate token read from Keychain/app config.

**Non-goals (explicit):**
- The relay itself — exists (buddycloud dictate), proven live.
- The STT engine (F201.6.7) and ordbog-correction (F201.14) — consumed, not built
  here.
- Non-terminal targets — v1 resolves cc-sessions via terminal tab titles only;
  Chrome-tab → session (or other app→target mappings) is a later extension.
- Silent/auto send without a visible target — always show "taler til" first
  (safety).

## Dependencies

- F201.6.7 Apple STT (capture), F201.14 ordbog-correction (true words before
  relay), buddy dictate relay (live), FocusWatcher (app+tab focus), buddy
  `list_sessions` (session roster for the picker).

## Rollout

1. Mode toggle + focus→session resolver + "taler til" indicator (read-only — show
   the target, don't send yet).
2. Wire Prompt-Mode dictation → correct → relay; token from Keychain.
3. Live-verify: dictate from the app while focused on an iTerm tab → the corrected
   text lands as a user turn in that exact session (runtime proof, not a claim).

## Open questions

- Token storage: Keychain vs a config file (lean Keychain — real credential).
- Tab-title → session-name robustness: exact iTerm title format (may be
  decorated/upper-cased); fall back to the manual picker when unsure.
- Auto-send vs stage-for-review: dictate lands + Enters immediately; do we want a
  per-mode "review before send"? (default: send, matching the proven behaviour.)
- **HUD steals frontmost** — `HudController.show()` calls `NSApp.activate`, so
  while the HUD is up Trail Ambient is the frontmost app, not iTerm. The resolver
  must SNAPSHOT the target from the app focused just BEFORE the hotkey/HUD fired,
  and auto-update the `Target` label only from real app switches — never resolve
  to Trail Ambient itself. (Capture on `captureToggle`; ignore own bundle id.)
