# F201.12 — Ambient-tilstand (one toggle: self-managing ambient KB)

**Parent:** F201 Trail Ambient Capture
**Status:** in progress
**Depends on:** F201.8 (per-KB auto-approve), F201.11 (distill verdict), F200.1 (contradiction-lint toggle endpoint)

## Motivation

F201.11 (distill) + F201.8 (auto-approve) are live: distilled *knowledge*
auto-approves into a Neuron at `/neurons/auto/`, unattended. But the ambient
promise — "an assistant that does NOT hand me more manual, boring work" — is
still broken in two places that keep re-filling the curator queue:

1. **Noise still parks in Pending.** F201.11's distill correctly classifies a
   Finder folder-listing or a bare Chrome tab-title as `verdict: 'noise'` and
   zeroes its confidence — but then *keeps it as a pending candidate* "for
   audit" (`queue.ts` distill block). Confidence 0 < threshold 0.5 so it never
   auto-approves — it just sits in Pending waiting for a human to click Reject.
   Observed 2026-07-02: two `distill:"noise"` captures (Finder, Chrome) sitting
   at conf 0.00 in `ambient-test`'s Pending, exactly the manual work ambient was
   meant to remove.

2. **"Make a KB ambient" is two coupled toggles.** To get a self-managing
   ambient KB the user must know to flip *both* auto-approve ON (F201.8) *and*
   contradiction-lint OFF (F200.1 — near-duplicate ambient Neurons otherwise
   flood the queue with contradiction candidates, the anticipated F200.1 case).
   Two levers that must move together is exactly the "I need to be the assistant
   myself" frustration.

## Goal

One per-KB **"Ambient-tilstand"** toggle. When ON, the KB self-manages with zero
human triage:

- distilled **knowledge** (conf ≥ threshold) → auto-approve (F201.8, unchanged);
- **noise** (`distill:'noise'`) → **auto-reject** — drops out of Pending,
  persisted as `rejected` (reason `ambient-noise (auto)`) so the **Rejected** tab
  keeps the audit trail for tuning the distill prompt;
- contradiction-lint → OFF (bundled, so near-duplicate ambient Neurons don't
  regenerate the queue).

Net effect: an ambient KB's **Pending queue stays empty**. The user reviews
nothing on an ambient KB unless they choose to.

## Non-goals

- Dedup / supersession / decay of ambient Neurons (later — F182 family already
  owns lifecycle; ambient will lean on it, not reinvent it here).
- A new `ambient_mode` column. **Ambient mode = `auto_approve_threshold IS NOT
  NULL`** — reuse the F201.8 signal; the toggle just also drives the lint flag.
- Any change to non-ambient KB behaviour. Threshold `null` → noise stays pending
  exactly as today (ship-dark preserved).

## Architecture

### Backend — symmetric auto-reject (packages/core/src/queue/policy.ts)

Add, beside `shouldAutoApprove`:

```ts
function isAmbientNoise(candidate): boolean   // metadata.distill === 'noise'
export function shouldAutoReject(candidate, kb?: AutoApproveKbPolicy): boolean {
  const t = kb?.autoApproveThreshold ?? null;         // null = ambient mode OFF
  return t !== null && isAmbientCandidate(candidate) && isAmbientNoise(candidate);
}
```

`enqueue()` (candidates.ts) already loads the KB's `autoApproveThreshold`. Before
the `shouldAutoApprove` branch, add:

```ts
if (shouldAutoReject(candidate, kbPolicyArg)) {
  const approval = await resolveCandidate(trail, tenantId, id, actor,
    { actionId: 'reject', reason: 'ambient-noise (auto)' }, { auto: true });
  return { candidate, approval };   // status 'rejected', never pending
}
```

The queue route's `candidate_created` broadcast must reflect the *true* resolved
status (`result.approval?.status ?? 'pending'`), not assume `approved`, so a
noise auto-reject doesn't flash as approved in the live UI.

### Frontend — bundled toggle (apps/admin/src/panels/settings-trail.tsx)

The F201.8 "auto-approve" toggle becomes **"Ambient-tilstand"**. Its handler
issues both writes in one action:

- ON  → `updateKnowledgeBase(id,{autoApproveThreshold:0.5})` **and**
        `updateLintSettings(id,{contradictionLintEnabled:false})`
- OFF → `updateKnowledgeBase(id,{autoApproveThreshold:null})` **and**
        `updateLintSettings(id,{contradictionLintEnabled:true})`

Toggle state reads `autoApproveThreshold` (now returned by the KB-list after the
`84ff04f` projection fix). `data-testid`: `settings-ambient-mode-toggle` /
`settings-ambient-mode-state`.

## Acceptance criteria

1. **Noise auto-rejects only in ambient mode.** A verify script POSTs an ambient
   candidate with `metadata.distill:'noise'` to a KB with
   `autoApproveThreshold=0.5` → resolved status `rejected` (not pending); the
   same POST to a KB with `autoApproveThreshold=null` → stays `pending`.
2. **Knowledge path unbroken (F201.8 regression).** An ambient candidate with
   `distill:'knowledge'`, conf 0.8, to an ambient-mode KB → still auto-approves
   (status `approved`, Neuron at `/neurons/auto/`).
3. **One toggle drives both settings.** Toggling Ambient-tilstand ON sets
   `autoApproveThreshold=0.5` AND `contradictionLintEnabled=false`; OFF sets
   `autoApproveThreshold=null` AND `contradictionLintEnabled=true` — verified by
   reading both back from the live KB after each flip.
4. **Live: empty Pending.** After a `distill:'noise'` capture arrives on
   `ambient-test` (ambient mode ON), its Pending count stays 0; the candidate is
   visible in the Rejected tab.

## Rollout

Ship-dark preserved by construction: everything keys off
`auto_approve_threshold IS NOT NULL`. KBs without it set behave exactly as
before. Deploy = engine (policy + route) + admin (toggle). No new env flag.
