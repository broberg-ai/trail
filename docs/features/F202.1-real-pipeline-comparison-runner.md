# F202.1 — Real-pipeline comparison runner + config CLI

## Design principle (Christian, 2026-07-08)

**Model-lab must mirror our production ingest setup 100% — same
`buildCompilePrompt`, same `createCandidateQueueAPI`, same tool-loop, same
`@broberg/ai-sdk` routing — with the SINGLE limitation that it runs against an
artificial/ephemeral KB (a throwaway temp libSQL DB), NOT a real cloud KB and
not writing Neurons into a customer tenant.** Everything else is identical to
what a real ingest run executes.

## What ships

A reusable `runIngestComparison({source, models, facts, maxTurns})` +
`compare-cli.ts`. For each model:

1. Seed a throwaway `TrailDatabase` (temp libSQL, `runMigrations` + `initFTS`),
   a tenant/user/KB, and the source as a `documents` row — identical seed to
   the real ingest job shape.
2. Build the prompt with the **production** `buildCompilePrompt(trail, job,
   doc, kb)`.
3. Resolve the model's provider from the registry → invoke the **REAL backend
   class** (`new MistralBackend()` / `new OpenRouterBackend()`) `.run(input)`
   with `input.model` pinned. Do NOT re-implement the tool loop — calling the
   prod backend guarantees parity and is drift-proof (the loop lives in ONE
   place). The backend already routes through `@broberg/ai-sdk`.
4. After the run, read the produced `kind='wiki'` Neurons and score:
   grep-based **fact recall** against the optional ledger, plus neuron-count,
   cost (from the SDK usage), duration, turns.
5. Persist to `model-lab.db` (reuse `db.ts`), tagging each row EU/non-EU from
   the registry.

## Config surface

`bun run compare-cli --source <file|source-id> --models all|<comma-list> \
  [--facts <ledger.json>] [--max-turns 30]`

- `all` → enumerate `INGEST_MODELS` (packages/shared) + lab-only comparison
  models. A comma-list picks a subset by id.
- `--facts` → JSON `[{"id":"F1","needle":"Fodsved"}, ...]`; omit to skip recall
  (then only count/cost/duration).

## Reuse / retire

- **Reuse:** `db.ts`, the compare UI, `INGEST_MODELS` registry, the prod
  backend classes + `buildCompilePrompt` + `createCandidateQueueAPI`.
- **Retire (later, F202.3):** `openrouter.ts` (hand-rolled loop), `tools.ts`
  (simulated KB), `prompt.ts` (old prompt) — replace → prove → remove.
- **Single-source note:** if importing `buildCompilePrompt` from `apps/server`
  into `apps/model-lab` is awkward (cross-app), lift it to `@trail/core` so
  both consume one copy (tracked as a follow-up task under F202).

  — same recall/cost/duration table, no bespoke script.
