# F163.3 — Image-detail Lightbox port (CMS-style: side-panel + EXIF + tags + pagination + toolbar)

> Genskab CMS-projektets image-viewer-design i Trail's Lightbox: image fylder venstre 70%, side-panel 30% til højre med caption + alt-text + tags-editor + EXIF data, top-right toolbar (open-in-tab, copy URL, re-scan, delete), keyboard-pagination ←/→ mellem billeder i nuværende hits-liste. Multi-locale caption (DA/EN/DE-tabs) er **ikke** med i v1 fordi det kræver enten 3x Vision-cost eller F90 translate-pipeline-extension. Sproget følger KB.language (Sanne = da, fix lander som F163.3.0). Tier: alle tenants. Effort: Medium-Large — ~1 dag opdelt i 5 phases. Status: Planned.

## Problem

F163's nuværende Lightbox er funktionel (image + caption + open-source/copy-URL/× luk) men minimalistisk. Christian peger på CMS-projektets `localhost:3010/admin/media` viewer som forbillede — et meget mere komplet image-detail-overlay med:

- AI-genereret caption + alt-text + tags (alle copy-able)
- Inline tag-editor (curator tilføjer/fjerner tags på selve billedet)
- EXIF metadata (camera, date, size, lens, aperture, shutter, ISO, focal-length)
- Top-right toolbar (åben i ny tab, copy, refresh, delete)
- Pagination mellem billeder i listen (← / → pile + index "12 / 430")
- Bottom-meta-strip (filename, size, dato)

Trail har data nok til at matche meget af dette: `vision_description` = caption, `vision_model` + `vision_at` audit, `auto_flag_signal` + curator-rating fra F164 Phase 5. Manglende: EXIF (kun standalone uploads kunne potentielt have), per-image tags (kun source-doc har tags i dag), pagination-state.

Konkret katalysator: Sanne har i dag set sit gallery på 309 billeder + 91 auto-flagged. Når hun klikker et billede vil hun gerne kunne:
- Se hvad Vision sagde (caption) — done
- Tilføje sine egne tags (fx "fod", "højre side", "kapitel 3") — **mangler**
- Slette direkte fra Lightbox uden at gå tilbage til list-view + multi-select — **mangler**
- Bladre gennem billederne uden at lukke + click + lukke + click — **mangler** (← / →)
- Re-scanne hvis hun synes Vision-beskrivelsen er dårlig uden at gå til list-view — **mangler**
- Se EXIF for foto-uploads (når hun begynder at uploade behandlings-billeder direkte) — **mangler**

Bredere: enhver tenant der bruger billed-galleri vil møde samme behov. CMS-viewer-mønstret er en velkendt lommespringer der reducerer antal-klik per cleanup-cykel betydeligt.

## Secondary Pain Points

- **Lightbox close-button er pænere men toolbar mangler stadig.** F163.3 placerer alle handlinger som ikon-buttons øverst (åben/copy/re-scan/delete) i stedet for at have dem nederst som tekst-knapper. Ikoner sparer plads og matcher CMS-mønstret.
- **Pagination kræver state-passing.** Lightbox må kende sin position i hits-arrayet for at kunne prev/next. Skal håndteres uden at re-fetche siden — lookup i in-memory hits.
- **EXIF-extraction kun ved upload-tid.** Re-scan af gamle uploads ekstraherer ikke EXIF nu. Sweep-job kan tilføjes senere (F163.3.x) hvis behovet opstår.
- **Single-image delete genbruger F163.1 bulk-endpoint** med imageIds: [id]. Ingen ny endpoint nødvendig.
- **Sprog-mismatch:** Vision-pipelinen kører engelsk hardcoded selv om Sannes KB.language='da'. Det skal fixes som F163.3.0 quick-fix FØR F163.3 lander så curator ser danske beskrivelser i den nye Lightbox.

## Non-goals (v1)

- **Ingen multi-locale caption** (DA/EN/DE-tabs i CMS-design). Kræver enten:
  - 3x Vision-cost (kalder Vision tre gange per billede), eller
  - F90 translate-pipeline-extension til image-descriptions (separat scope).
  Single-locale (KB.language) er nok i v1. v1.5 kan tilføje on-demand translate-button hvis curator efterspørger.
- **Ingen embed/share-link**. CMS-viewer'en har copy-URL men intet "share with anyone outside"-flow. Trail's image-URL kræver Bearer/session — det er konsistent med audience-filter-modellen og vi piller ikke ved det.
- **Ingen edit af caption/alt-text inline.** Vision-genereret tekst er read-only; curator kan re-scan men ikke håndredigere. Konsistent med F163.1 plan-doc's "ingen edit-mode for Vision-beskrivelser" non-goal. v2 kan tilføje hvis bagved-prompt-tuning ikke er nok.
- **Ingen drag-to-reorder eller bulk-tag-editor i Lightbox.** Lightbox er enkelt-billede-fokus; bulk-handlinger sker i list/grid-view via F163.1.
- **Ingen image-rotation eller crop tools.** Read-only viewer.

## Solution

### Schema-migrations

#### Migration 0029 — `document_images` EXIF-kolonner

```sql
ALTER TABLE document_images ADD COLUMN exif_camera TEXT;
ALTER TABLE document_images ADD COLUMN exif_lens TEXT;
ALTER TABLE document_images ADD COLUMN exif_taken_at TEXT;        -- ISO-8601
ALTER TABLE document_images ADD COLUMN exif_aperture REAL;        -- f-stop, e.g. 1.78
ALTER TABLE document_images ADD COLUMN exif_shutter TEXT;         -- "1/50" — string for fraction display
ALTER TABLE document_images ADD COLUMN exif_iso INTEGER;
ALTER TABLE document_images ADD COLUMN exif_focal_length REAL;    -- mm
```

Alle nullable — PDF-extracted images har ingen EXIF (host-PDF har, fragmenter ikke), AI-genererede billeder har ingen, screenshots har sjældent. NULL betyder "unknown / not applicable".

#### Migration 0030 — per-image `tags` kolonne

```sql
ALTER TABLE document_images ADD COLUMN tags TEXT;
```

Comma-separated string, mirror af `documents.tags`-mønstret. Tom = ingen tags. Ingen separat tabel nødvendig før vi får faceted search-behov.

### Backend

#### EXIF-extraction ved upload

Ny dependency: `exifr` (lightweight, ~30KB, parser EXIF/IPTC/XMP fra PNG/JPEG/HEIC). Add to `apps/server/package.json`.

I `apps/server/src/routes/uploads.ts` (F25-path for standalone images):

```typescript
import exifr from 'exifr';

// Inside the image-upload branch
const exif = await exifr.parse(buffer, {
  pick: ['Make', 'Model', 'LensMake', 'LensModel', 'DateTimeOriginal',
         'FNumber', 'ExposureTime', 'ISO', 'FocalLength'],
}).catch(() => null);

const exifFields = exif ? {
  exifCamera: [exif.Make, exif.Model].filter(Boolean).join(' ').trim() || null,
  exifLens: [exif.LensMake, exif.LensModel].filter(Boolean).join(' ').trim() || null,
  exifTakenAt: exif.DateTimeOriginal?.toISOString() ?? null,
  exifAperture: exif.FNumber ?? null,
  exifShutter: exif.ExposureTime ? formatShutter(exif.ExposureTime) : null,
  exifIso: exif.ISO ?? null,
  exifFocalLength: exif.FocalLength ?? null,
} : { /* all nulls */ };

// Pass exifFields when inserting/updating document_images row
```

`formatShutter(0.02)` → `"1/50"`. PDF-extraction-pipeline doesn't get EXIF (binary fragments aren't EXIF-tagged) — that's a feature, not a bug.

#### Image-row response shape extension

`images-search.ts` SELECT now includes the EXIF columns + tags. ImageHit on frontend gains:

```typescript
interface ImageHit {
  // ... existing fields ...
  tags: string[]; // comma-split
  exif: {
    camera: string | null;
    lens: string | null;
    takenAt: string | null;
    aperture: number | null;
    shutter: string | null;
    iso: number | null;
    focalLength: number | null;
  };
}
```

#### Tag CRUD

New endpoints:

```
POST /api/v1/documents/:docId/images/:filename/tags
  body: { add?: string[]; remove?: string[] }
  → { tags: string[] }
```

Single endpoint with diff-payload — simpler than separate add/delete. Sanitises tags (lowercase, trim, max-length 50, alphanumeric+hyphen). De-dupes with existing.
