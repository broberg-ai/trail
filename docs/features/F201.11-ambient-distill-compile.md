# F201.11 — Ambient distill-compile

> Turn a raw ambient screen-capture window into *extracted knowledge* before it
> becomes a Neuron. The prerequisite that makes per-KB auto-approval (F201.8)
> safe: you can only auto-approve unattended if the candidate is clean.

## Motivation

Ambient candidates are stored **verbatim** as Neurons — `external-feed` has no
compile step (the code notes: *"body is mostly user content that should stay
verbatim"*). But a per-window capture is ~1/3 signal (decisions, commitments,
facts about projects/people/customers) and ~2/3 noise: tab-lists, UI chrome,
code the user was merely *reading*, OCR fragments.

Live exhibit (2026-07-02, cb's Ambient Test): one 34-second window mixed a real
decision ("F156 = inline visible-text-only editing, commit ecb74667") and
personal decision-state ("F187 deferred, ikke carded — kræver dit ord") with a
Claude tab-list ("Music Quiz", "Social Media (NEW)", "Tailscale-alternativ") and
a DOMPurify code snippet he was reading. Verbatim, all of that becomes memory.

If we auto-approve verbatim (the F201.8 vision — no boring manual approval), the
assistant "learns" the noise: that you have a tab called Music Quiz, that
DOMPurify.sanitize exists. That is memory **pollution**, not a smarter
assistant. So auto-approval is only safe once the candidate is **distilled to
knowledge first**. This story is that distill step.

**Decision (2026-07-02, with Christian):** fix the *compile*, don't remove the
*queue*. He argued a curator judging whether what he does is "RIGHT" is
illusory — correct, that is not what the queue is for. The real problem is that
raw ambient is noisy and captures things that are not his knowledge. So the
queue stays (curation IS Trail's value for Sanne/customers), but for ambient
KBs it becomes a reversible ledger over CLEAN candidates, not a blocking inbox
over raw dumps. Not Trail-wide — per-KB.

## Scope (build)

- `packages/core/src/queue/ambient-distill.ts` — `distillAmbientCapture(input,
  ai)` → `{ verdict: 'knowledge' | 'noise', title, content, confidence }`. An
  LLM extraction pass (Danish, matching the KB language): keep decisions /
  commitments / facts; drop chrome, tab-lists, read-only content, OCR noise. A
  window with no durable knowledge → `verdict: 'noise'`.
- Wire into `POST /queue/candidates`: when `metadata.connector ===
  'trail-ambient-capture'`, distill BEFORE persist; replace title+content with
  the distilled knowledge, set confidence, stamp `metadata.distill`.
- Ship-dark behind `TRAIL_AMBIENT_DISTILL=1` on the engine.

## Non-Goals

- NOT the auto-approval policy itself (F201.8) — this only makes candidates
  clean enough to auto-approve safely.
- NOT on-device distill — stays engine-side; the Mac agent remains a thin
  capture + gate + redact + POST client (no LLM key on the Mac, thin-agent
  architecture principle).
- NOT touching non-ambient candidates (chat-answer, ingest-summary, curator) —
  they pass through unchanged.
- NOT silently dropping noise — a noise verdict is flagged + low-confidence
  (auditable, reversible), never deleted.

## Architecture

1. Relay (on-device, unchanged): `summarizeWindow` (raw OCR) → redact
   (`@broberg/secret-scan`) → POST.
2. Engine (new): on an ambient candidate, `distillAmbientCapture` runs via
   `@broberg/ai-sdk` on the **Mistral EU tier** (`override: { provider:
   'mistral', model: 'mistral-small-latest', transport: 'http' }`). GDPR:
   ambient data is personal/client data → EU-only, never a US model (F199
   directive). The input is already secret-redacted on-device. Only the
   DISTILLED knowledge is persisted; the raw window text is dropped after
   distill (provenance kept: `sourceUrl` + `capturedAt`).
3. Verdict `noise` → `metadata.distill='noise'`, confidence 0 → never
   auto-approves; filterable / prunable in the queue.
4. LLM failure → log-and-continue with the raw candidate (never lose a
   capture).

## Dependencies

- `@broberg/ai-sdk` shared `ai` client (`apps/server/src/lib/ai.ts`); Mistral
  adapter keyed off `MISTRAL_API_KEY` (Fly secret; absent locally → local
  proof uses an injected `ai`).
- Candidate-create path (`packages/core/src/queue`).

## Rollout

Deploy engine with `TRAIL_AMBIENT_DISTILL=1`. The already-running relay's POSTs
get distilled server-side — no agent update needed. Verify:
`verify-f201-11-ambient-distill.ts` (injected `ai`: EU routing + keep/drop
pipeline + noise verdict + non-ambient pass-through) locally; one real Mistral
EU call on the engine env distilling a real-shaped capture.

## Acceptance criteria

1. Mixed capture (real decision + tab-list/UI noise) → distilled content keeps
   the decision, drops the noise (fixture asserts inclusion + exclusion).
2. Pure-noise capture → verdict 'noise', `metadata.distill='noise'`, confidence
   0 (won't auto-approve).
3. Distill routes through `@broberg/ai-sdk` on Mistral EU (provider=mistral),
   never a US model — asserted by capturing the requested provider/model.
4. Only `connector=trail-ambient-capture` is distilled; chat-answer /
   ingest-summary / curator candidates pass through unchanged.
