# F201.19 — Sources deep-link opens on the 'all' tab

## Motivation

F201.18 made an Ambient source-hit open `/kb/<kb>/sources?expanded=<docId>`.
That reached the Sources view, but landed on the empty **'active'** tab — the
targeted dictation (a Source usually in 'success'/'archived') was filtered out,
so the pre-filled expand + scroll had no row to act on. Christian: "MEGET
urelevant."

## Root cause

`apps/admin/src/panels/sources.tsx`: `filter` defaults to `'active'`. The
`?expanded=<docId>` effect finds the doc in the full `allDocs`, but scrolls via
`document.querySelector([data-doc-id=…])` — which only matches a RENDERED row.
The rendered list is narrowed to the active `filter`, so a doc outside 'active'
is never in the DOM → no expand, no scroll → empty tab.

## Fix

When a `?expanded=` param is present, start the panel on **'all'** so every
Source renders regardless of status; the existing pre-fill (expanded-set) +
scroll effect then open the targeted row and show its content. One-line change
plus moving the `expandedFromUrl` memo above the `filter` useState:

```ts
const [filter, setFilter] = useState<FilterStatus>(expandedFromUrl ? 'all' : 'active');
```

No change to the no-deep-link default ('active'), the tab counts, or the
expand/scroll effect.

## Scope

**In:** the filter-default change in `sources.tsx`. **Out:** a dedicated
full-page source reader (a nicer experience than the list+expand, but a larger,
separate piece if the list-expand still feels clunky).

## Verification

- apps/admin typecheck clean; redeploy trail-admin (also ships the F201.18
  `wikiReader.notFoundTitle` i18n key).
- Live: opening a source deep-link lands on 'all' with the row expanded/scrolled
  showing the dictation content, not the empty 'active' tab.
