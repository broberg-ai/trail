# F191.8 — Auto-dispatch (parked sources drain themselves, hands-off)

**Parent:** [F191 — Local Ingest Station](F191-local-ingest-station.md)
**Status:** building
**Owner:** trail cc session

## Motivation

F191.1–.7 made the local-ingest pipeline work, but the **trigger** was never
wired: parking a source (`awaiting_local_compile=true`) notifies nobody, so the
Station banner just says "run `/local-ingest …`" and **nothing happens** until a
human types the command. Christian's requirement: **100% automatic** — drop a
file, watch it become Neurons, no command.

## The hard constraint that shapes the design

$0 compile **requires an interactive cc session on the Max plan** — a headless
`claude -p` / cron drain is API-billed and breaks the $0 premise. So the
automation can NOT "compile by itself"; it must **(a) detect pending sources**
and **(b) instruct an already-running interactive cc session to drain them.**

The cloud engine can't reach the local Mac, so detection must be a **local
poller** of the cloud `?awaitingLocalCompile=true` endpoint.

## Scope

Two homes, shipped in sequence (Christian's call: "begge"):

### A. Interim — loop in the trail cc session (see-it-work-now)
The trail session (an interactive $0 session) runs a self-paced poll loop
(~90–120s): for each tenant the key reaches (broberg-ai + sanne-andersen),
`GET …/documents?awaitingLocalCompile=true`; if any are pending, run the
`/local-ingest` drain (incl. F191.7 local vision); else idle. Works immediately
and is genuinely $0 (this IS an interactive session), but only while the session
is open.

### B. Durable — buddy poller + dispatcher (always-on)
buddy (always running, monitors every cc session) polls the same cloud endpoint
every ~60s. When a tenant has pending sources, buddy **dispatches a drain to an
interactive cc session via intercom** (the trail session) — the upmetrics-
remediation pattern F191.2 referenced. Crucially it dispatches to a RUNNING
interactive session (Max, $0), NOT a freshly-launched headless agent (which
would be API-billed). Survives the trail session being closed; only pokes a
session when there's work (no busy-loop). Implementation lives in the buddy
repo — coordinated via the buddy peer session.

**Non-goals:**
- Headless/cron auto-compile — breaks $0 (the whole reason this is poll+dispatch
  to an interactive session, not a server job).
- A new launchd daemon (`apps/agent` is referenced in the layout but doesn't
  exist; not building it just for this — buddy already is the local always-on
  orchestrator).
- Auto-approving the resulting Neurons beyond the existing queue policy.

## Architecture

```
Drop file (Station, localCompile=true) → parked on cloud (awaiting_local_compile=true)
        ▲ cloud — can't reach the Mac
        │  poll  GET …/documents?awaitingLocalCompile=true   (per tenant, multi-tenant key)
   ┌────┴─────────────────────────────┐
   │ LOCAL poller                      │
   │  A. trail session loop (interim)  │ → runs /local-ingest in THIS session ($0)
   │  B. buddy (durable)               │ → intercom "drain <tenant> <kb>" → trail session ($0)
   └───────────────────────────────────┘
                 │ /local-ingest (F191.2 + F191.7 vision) → wiki-write → /local-compiled
                 ▼
        Neurons appear in the Station / KB  (connector mcp:claude-code)
```

## Verification

- A: with the loop armed, drop a real file → within one poll interval the trail
  session drains it → Neurons appear, banner clears, no human command.
- B: close the trail session's loop, have buddy detect a parked source and
  intercom the trail session → it drains. Confirm no headless `claude -p` is
  spawned (stays $0).

## Rollout

1. Arm the trail-session loop now (interim A) so the flow is demonstrable today.
2. Coordinate the buddy session to implement the poller + intercom-dispatch (B);
   once live, the interim loop can be retired.
